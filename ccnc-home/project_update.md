# ccNC on GEN5W — Project Update

*2026-11-21*

## Goal

Replace the dated GEN5W (Ioniq 6 CEEV, Android 4.4 KitKat, 1920×720 @ 240dpi, firmware KVT49L) stock app UIs with apps styled after Hyundai/Kia **ccNC**, using the exports in `apps/` (CCNC reference: stripped aarch64 Qt binaries + image assets + embedded QML) as the design source. Install model is **hide-and-replace**: our APKs use new package names (`dev.ccnc.*`), and the ccnc-home launcher hides the stock cards and points at ours.

## Repo layout (GEN5W/)

| Folder | What |
|---|---|
| `ccnc-home/` | Launcher (`dev.ccnc.home`), v1.4 |
| `ccnc-weather/` | Weather (`dev.ccnc.weather`): current, details, 5-day forecast |
| `ccnc-phone/` | Phone (`dev.ccnc.phone`): keypad, recents, contacts; dials via the Broadcom HF profile |
| `ccnc-radio/` | Radio (`dev.ccnc.radio`): AM/FM/FM2, seek, 6 presets, RDS name/text via MicomRadioManager |
| `ccnc-voicememo/` | Voice Memo (`dev.ccnc.voicememo`): AAC recorder, list, playback |
| `ccnc-profile/` | Profile (`dev.ccnc.profile`): Guest/Driver 1/2, active profile; manage opens stock |
| `ccnc-ev/` | EV (`dev.ccnc.ev`): SOC ring, range, charging, targets, odometer (read only) |
| `ccnc-navi/` | Navigation hub (`dev.ccnc.navi`): opens the MnSoft map at search / position / menu / setup, nearest-charger lookup |
| `ccnc-welcome/` | NEMESIS package: ccNC startup video (`ccnc.welcome`) |
| `ccnc-common/` | Shared toolkit: subsetted CCNC fonts, palette, Bg, Widgets; `build-fonts.sh` (7 MB → 48 KB per weight via pyftsubset; venv at `/tmp/fontenv`) |
| `ccnc-settings/` | Settings hub (`dev.ccnc.settings`) |
| `ccnc-climate/` | Climate panel (`dev.ccnc.climate`) |
| `ccnc-media/` | Media home (`dev.ccnc.media`) |

All builds are plain-SDK (`aapt2`/`javac`/`d8`/`apksigner`, min/target SDK 19), no Gradle. Fonts load from assets with Mobis/system fallback; brand bundle chosen via `persist.sys.ccnc.brand` (default hyundai, kia available).

## Done

- **ccnc-settings** — two-pane hub (Vehicle/Display/Sound/Bluetooth/Wi-Fi/Appearance/General/Bluelink/System). Rows launch the stock settings activities (components from the KVT49L launchable-activity list); Wi-Fi/Bluetooth have live toggles. Launcher: Setup card → hub, stock settings apps hidden by default.
- **Launcher: CCNC-style drag-to-rearrange** — mined from the `homehmi` export (embedded QML: press-and-hold drag, center hotspot, DropArea = half-self + half-neighbor insertion; `hom_bg_widget_edit_card` dim-to-50% edit outline; `pop_bg_guide_edit_home` first-run scrim guide). Implemented: long-press grabs a card (lifted/lit, siblings dim 50% with pale outline), drag with live slide animations, edge auto-page-flip, ring-minus badges to hide, first-run guide overlay once, dedicated edit toolbar row ("Drag to rearrange" + Done), Back/Done exit. Old Move left/right dialog removed.
- **ccnc-climate** — driver/passenger temp steppers (0.5 °C steps, LO/HI ends, °C/°F), fan bar (tap-to-set 1–8), 5 modes, Power/Auto/A/C/Recirc/Front/Rear pills, seat heat/vent 3-step. Sources: `DatcSource` (vehicle) / `DemoSource`.
- **ccnc-media** — source launcher (Radio/USB/BT/CarPlay → stock apps), now-playing card (title/artist/album, progress bar + times), transport buttons sending global media key events (`AudioManager.dispatchMediaKeyEvent`). Metadata via `RemoteController` (API 19) when permitted. Demo source with ticking clock otherwise.
- **Launcher integration** — Climate card → `dev.ccnc.climate`, Media card → `dev.ccnc.media`; stock climate (`com.hkmc.telematics.service.apps.climate`) and MediaGate hidden by default.
- All 4 APKs build and verified on a 1920×720 API 36 emulator (adb install needs `--bypass-low-target-sdk-block` there; not needed on the unit).

- **Launcher 1.4** — welcome landing page (greeting by phone owner, big clock/date, weather + connected-phone widgets; toggle in the long-press menu), real ccNC 90px icons (hyundai/kia) on cards, ccNC fonts, ccNC Nebula/Starfield wallpaper themes (Nebula default; Auto = Day by day, Nebula at night), NEMESIS card, connected phone name on the CarPlay/AA card (`PhoneInfo`: Broadcom HF proxy, ACL fallback). On the car it is now explicitly **view only** (the stock app only writes rear-seat/voice paths and the odex hides the control ids, so no guessed vehicle commands); the launcher keeps the stock climate card ("Climate (stock)") visible.

Time units and `playstate` values are guessed (seconds-or-ms heuristic, 1 = playing): check the `ccncMedia` log on the car.
- **Packaging** — `ccnc-apps` (Settings+Climate+Media, id `ccnc.apps`), `ccnc-welcome`, `ccnc-home`; `./ccnc-release.sh` builds all and `dist/ccnc-all-nemesis.zip`, a Package Store stick listing them.

- **Climate redesign (v2)** — rebuilt as a single painted panel from ccNC's own climate art (`ccnc-common/assets/ccnc/climate`): seats with heat (orange) / vent (blue) glow per level, big temperature with red/blue chevrons and the cold-hot gauge, the dash with air-flow arrows (face / face+feet / feet / defog), 8-step fan gauge, AUTO / A/C / SYNC / RECIRC / REAR / POWER. Interactions tested on the emulator; view only on the car.
- **Weather app** — `WeatherFeed` (ccnc-common) reads the full parcel: humidity, wind, rain chance, sun times, forecast list (`ReadAndSaveForecastWeatherInfo`: min/max temp, icon, rain). ccNC condition icons (day/night) chosen from the stock condition text. Units guessed: wind shown as m/s; forecast `weatherTime` format assumed `yyyyMMdd…`; sun times assumed `HHmm` — check `ccncWeather` log on the car.
- **Phone app** — contacts/recents from the standard providers, dial through `BluetoothHfDevice.dial()` (tel: fallback). Not tried against a real paired phone. Launcher shows it as "Phone", the stock one as "Phone (stock)".
- **Manifest bug** — Settings, Climate and Media had `category.Launcher` (wrong case) so they never showed as apps; all fixed. All APKs now bundle the shared ccNC assets (~1.1 MB each).
- **Radio / Voice Memo / Profile / EV apps** — Radio drives the tuner through `com.hkmc.media.MicomRadioManager` (compile-time stubs in `ccnc-radio/src/stubs`, kept out of the dex; band ids AM1 0x71, FM1 -0x7f, FM2 -0x7e; frequency unit heuristic covers 10 kHz and kHz). Voice Memo records AAC ADTS with MediaRecorder (tested on the emulator). Profile reads `UserProfileManager.getUserType()/getUserName(id)`. EV reads `HEVManager.getHEVStatus(flag)` with the HEVFlag ids (DISPLAY_SOC 0x19, ELECTRIC_DTE 0x9, TOTAL_DTE 0xb, TRIP_UNIT 0xc, CHARGE_STATE 0x7, CHARGING_INTEGRATED_REM_TIME 0x15, TARGET_SOC_SLOW/QUICK 0x22/0x23, FAST_CHARGING 0x28, STD_CHA 0x1c, ODOMETER 0x1f). **All unverified on the car**: whether a non-system app may call these services, SOC scaling (0.5 % steps handled), TRIP_UNIT meaning (0 = km assumed), remaining-time unit (minutes assumed). Check the `ccncRadio`, `ccncEv`, `ccncProfile`, `ccncMemo` logs. Stock cards stay visible as "(stock)".
- **Navigation hub** — the MnSoft map (`com.mnsoft.navi`) draws its own screen so it can't be restyled; `ccnc-navi` wraps it: Map, Search, Current position, Menu, Settings via `com.hkmc.intent.action.ACTION_NAVI_SHORTCUT/TOTALSEARCH/CURRENTPOS/MENU/SETUP` (sent after opening the app), and a nearest-charger card (`com.hkmc.telematics.gis.action.REQUEST_/RESPONSE_NEAREST_CHARGING_STATION`; response extras NAME, REMAIN_DISTANCE(+_UNIT), LAT, LON assumed, raw extras logged as `ccncNavi`; navigate sends `START_NAVIGATION` with LAT/LON/NAME). Unverified on the car.
- **Climate control (opt-in)** — `getClimateInfo(id)` now feeds the screen (ids from DATCFlag$DATCControl: AUTO 8, AC 9, BLOWER_LEVEL 5, BLOWER_MODE 6, INTAKE 0xb, FRONT_DEFOG 0xa, SYNC 0x16; raw values logged as `info id=… value=…`). Writes go through `setFrontClimateControl(0x41)` only when `supportFrontClimateControl()` is true AND the owner turned on "Vehicle control" (off by default, confirm dialog). Encodings assumed (toggles 1/0, SYNC 0 = linked, temp UP/DN 1/2, OFF_REQ 1) and logged as `SENT …`: confirm each on the car.
- **Run `./ccnc-verify.sh` at the car** — opens every app, screenshots, collects the logs into REPORT.txt.
- **Navigation (earlier note, superseded)** — com.mnsoft.navi renders its own map (navi_app.bin, 491 MB engine); there is no Android view tree to restyle. Only its card is ccNC-styled.
- **EV (earlier note, superseded)** — `com.hkmc.hev.HEVManager` only exposes charge scheduling / departure time / V2L settings (HCU041-054, OBC011/014 indices); SOC/range are not there. Stock HKMC_TAppEV3 is obfuscated; needs a deodex of its data layer (`ev3/a/f`) plus a car session. Left as the stock EV card.

- **Service access, checked statically (automotive-service.odex deodexed)** — `DATCService`, `HEVService` and `UserProfileService` enforce no caller permission in their transaction paths (only `android.permission.DUMP` inside `dump()`), so a non-system app may call them. `RadioService` enforces `com.hkmc.permission.ACCESS_RADIO` on its calls; every `com.hkmc.permission.*` in hkmc-res.apk is protectionLevel 0 (normal), so it is simply granted at install. ccnc-radio did not request it (it would have been refused): now declared, along with ACCESS_NAVIGATION (navi), AUTOMOTIVE_HVAC/STATE (climate), AUTOMOTIVE_STATE (ev, profile). Service names come from `com.hkmc.Service.*_SERVICE` (climate now reads `DATC_SERVICE` from the unit, literal as fallback). Our launcher already reached ModeManager over binder on the car, so binder access from an app is proven there. Still open on the car: the *values* (encodings, units, scaling), not access.

- **Climate control ids, confirmed from the server** — `DATCService.setFrontClimateControl` switch: 0x4 MainBlowerUpDn, 0x5 MainBlower, 0x6 FrontModeSet, 0x7 AirCleaningSet, 0x8 AutoSet, 0x9 AcSet, 0xa FrontDefog, 0xb IntakeSet, 0x16 SyncSet, 0x18 DrvOnlySet, 0x1c/0x1d Dr/PsTempSetC, 0x1e/0x1f …SetF, 0x20 DisScrnSet, 0x30 HeatSet, 0x31/0x32 Ps/DrTempUpDn, 0x33 MainBlower=0 (off), 0x34 haptic. The byte value is passed straight to the micom (signal table not in the firmware): toggle/UpDn encodings remain assumed. Fan: the stock UI only sends 2..9 for its 8 steps, now used (level+1). HEV `getHEVStatus` returns the raw cached value (`mHEVStatusCache`); scaling/units are set where the cache is filled, which I did not find statically.

- **Radio units, confirmed from MicomRadioConstants** — FM is 875..1080 in 0.1 MHz units (FM_HIGH 0x438, step 2), AM up to 1620 kHz (AM_HIGH 0x654). ccnc-radio formatting fixed (the earlier 10 kHz assumption would have shown 107.1 as "10.7").

- **Themes (shared)** — `ccnc-common/Themes.java` holds 11 themes (ccNC Nebula + Starfield wallpapers, Hyundai Blue, Midnight, Graphite, Ocean, Sunset, Forest, Ember, Mono, Day) and 9 accent colours; `Palette` is now dynamic and `Bg` draws the wallpapers. ccNC Home serves the owner's choice through `content://dev.ccnc.home.theme/theme` (read-only, no permission) and every ccNC app applies it at launch (`Themes.apply`), so one change in the launcher menu (Theme… / Accent colour…) reskins all apps. (A `Settings.System` route was tried and dropped: modern Android refuses custom keys.) Apps already open keep their old theme until reopened.
- **Stacked cards** — long-press the date bar → Stack cards… (pick a front and a back card; max two per stack; Remove a stack…). The back card peeks above the front with its name; tap the strip to see a screenshot of that app's page (12 bundled previews captured from the apps: `ccnc-common/assets-preview`, launcher only) with Open / Bring to front. Stocks apps with no screenshot show their icon. Stacks persist (`stacks` pref); the back card leaves the grid.
- **Driver assistance (ccnc-settings)** — new Settings category and screen `DriverAssistActivity`: 8 groups (Forward safety, Blind-spot, Lane, Parking, Driver attention, Cruise and highway, Speed limit, Warnings), ~40 settings from the stock VehicleSetting list (`DriverAssistance_*` keys; USMManager `getAssistance_*`), each group with ccNC's illustration. 209 driver-assistance graphics (sedan set, from `usm_da_*`, `Lane_safety_*`, `set_bg_*driver_assistance*`, `ccs_ic_adas`) are bundled in the Settings APK only (`ccnc-common/assets-da`). Values are shown as raw codes (they are multi-state, e.g. 0..7, not plain on/off), read-only: these are safety systems, so changes open the stock screen (VehicleSetting, then the `com.mobis.intent.action.DRIVER_ASSISTANCE_SHORTCUT` broadcast). Unverified on the car: that the shortcut lands on the driver-assistance page, and the code values (log tag `ccncDA`).

- **Stacks, redone (v1.5)** — a stack is now two half-height cards sharing one slot (each opens its own app); previews removed at your request: each half is a plain compact card. Long-press the date bar → Stacked cards… (top card, then the card under it; remove a stack). Screenshots: `ccnc-home/screenshots/`.
- **Icons, one set** — every launcher card uses ccNC's 90 px icon set (apps without a ccNC icon get ccNC's generic one instead of their own icon or line art; the CarPlay / Android Auto logos stay as the real logos); Settings' rail uses the same set.
- **Settings, migrated** — categories in ccNC order, all with ccNC icons: Driver assistance (native, ~40 settings), Vehicle (native `VehicleSettingsActivity`: every `get<Group>_<Setting>()` on `USMManager` discovered by reflection, ~300 settings in 19 groups, raw codes, "can be changed" flag), Electric vehicle, Display, Sound, Bluetooth (switch), Wi-Fi (switch), Device connections, Appearance (native `AppearanceActivity`: themes + accent, writes through ccNC Home's theme provider), Profile / Digital key, General, Bluelink, System (NEMESIS, Android). Display, Sound, General, Bluetooth/Wi-Fi detail, Bluelink and Button settings still open the stock screens that hold those controls. Vehicle values are read-only (codes are multi-state; the car's option lists live in the stock app).

- **Display page (native, read only)** — `DisplayActivity` reads the unit's `com.hkmc.setup.VideoSetupManager` (brightness, contrast, saturation, hue, day/night dimming, minimum/last manual level, light sensor, rheostat). Writes are deliberately left to the stock screen: DisplaySettings applies a brightness to one of four modes (auto/day/night/manual, `VideoSetupConstants$Dim`) with range checks I could not fully recover, and a wrong write could leave the screen unreadably dim. Settings keys it uses (`Settings.System`: user_bright, manual_bright, daylight_bright, night_bright, adm_notification, clock types) are known if a safe write path is wanted later.

- **Native Bluetooth / Wi-Fi / Sound / General pages (ccnc-settings)** — standard Android APIs, so these work without the car's private services: Bluetooth (switch + paired devices), Wi-Fi (switch, current network with signal, saved networks, tap to connect via `WifiManager.enableNetwork`), Sound (stream volumes for media/call/notification/alarm/system with sliders via `AudioManager`; the car's equalizer/sound field/beep stay in the stock screen and the car may apply its own curve on top), General (language, region, time, date, clock format, zone, build). Pairing new devices, hotspot setup, equalizer and language/date changes still open the stock screens. Bluelink and Button settings are not migrated: no data source recovered. Screenshots in `ccnc-home/screenshots/8-11`.

## Vehicle interfaces (from the smali dump, `analysis/automotive_smali`)

- **Climate**: `ServiceManager.getService("com.hkmc.micom.datc")`, AIDL `com.hkmc.datc.IDATCService`. Codes recovered: `getClimateType=0x1f`, `getClimateInfo(int)=0x26`, `isUnitCelsius=0x6`, `registerDATCListener=0x1`, `setDatcUSM(IZ)=0x38`. Listener `IDATCListener`: `onTemperatureInformation(F,I×7)=0x1`, `onDatcStatus(DatcStatus parcel)=0x3`. `DatcSource` connects + reads temps/unit and logs the status parcel; writes are **not yet mapped** (need `setDatcUSM` user-switch codes — recover from the stock climate app's smali during a bench session).
- **Media**: transport = global media key events (works with stock players). Now-playing = `RemoteController` on AudioManager; on HKMC builds likely needs install as system app (we have NEMESIS root) or `MEDIA_CONTENT_CONTROL`.
- Useful actions found: `com.hkmc.intent.action.CLIMATE` (opens stock climate), plus per-source shortcut broadcasts.
